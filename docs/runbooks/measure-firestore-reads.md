# Firestore の読み取り回数を計測し、月額を見積もる

Mastodon API の主なエンドポイントが 1 回のリクエストで Firestore を何回読むかを、
エミュレータ上で数える。読み取りを減らす変更の前後で同じ計測をし、効果を確かめるのに使う。
スクリプトは `functions/test/measure/firestore-reads.measure.ts`。

## 実行

```bash
npm --prefix functions run measure:reads
# 結果を JSON でも残すとき
MEASURE_OUT=/path/to/result.json npm --prefix functions run measure:reads
```

- エミュレータの起動からデータの投入まで含めて 5 分ほどかかる。
- 通常の `npm test` には含まれない(`vitest.measure.config.ts` で別に走らせる)。
- 変更の前後を比べるときは、`git worktree` などで前のコミットを取り出して同じコマンドを実行する。
  このスクリプトが入る前のコミットでは、スクリプトをコピーして `clearMastodonIdCache` の呼び出しを外す。

## 出力

標準出力に、リクエストごとの読み取り回数・返った件数・コレクションごとの内訳の表と、月額の見積もりが出る。

- `(cold)` が付いた行は、インスタンス内のキャッシュ(ADR-0135、ADR-0138、ADR-0139)が空の状態の 1 回目。
  付いていない行は 2 回目で、ウォームなインスタンスでの定常状態に当たる。
- ホーム・リストの `(rebuild)` は、タイムラインの先頭ページのキャッシュ(ADR-0139)だけを捨てて組み立て直した回、
  付いていない行はそのキャッシュが効いた回(検証の読み取りだけ)。`(new entry)` は新着が 1 件あって、新着分だけを
  組み立てて足した回。
- 数え方は課金規則に合わせている。`getAll`(`DocumentReference#get` を含む)は引いたドキュメント数、
  クエリは返った件数(0 件でも 1 回)。トランザクション内の読み取りと集計クエリ(`count()`)は数えない。

## データの規模

PR #346 の計測に合わせている。

- フォロー 280 人(40 のリモートのドメインに分散)。
- Note 2,800 件(各 10 件。うち 2 割はほかの人の Note へのリプライ)、Announce 840 件(各 3 件)。
- 30 人のリスト(`replies_policy: list`)。
- 自分の Note 20 件と、それへのリモートからのお気に入り 120 件(通知)。
- ホーム・リストのタイムラインの射影(ADR-0136)は有効にしてある。

## 月額の見積もりの前提

PR #346 と同じ。Phanpy の「タイムライン投稿を自動更新する」をオンにして、通知・ホーム・リストを 24 時間表示する。

| 項目 | 回数 / 月 |
|---|---:|
| ホーム・リストの先頭ページ(各カラム 15 秒ごと) | 各 172,800 |
| うち組み立て直し(先頭ページのキャッシュの TTL 15 分ごと。→ ADR-0139) | 各 2,880 |
| 通知のポーリング(`limit=1&since_id=…`、20 秒ごと) | 129,600 |
| 通知の読み直し(`limit=80`、新着 1 日 30 件) | 900 |

ホーム・リストは、60 回に 1 回を `(rebuild)` で数える。残りは、15 秒の間に新着が 1 件以上届く割合
(新着がポアソン過程で届くとして `1 - exp(-1 日の新着数 × 15 / 86400)`)を `(new entry)`、それ以外を 2 回目の値で数える。
1 日の新着数は環境変数 `MEASURE_HOME_ENTRIES_PER_DAY` / `MEASURE_LIST_ENTRIES_PER_DAY` で上書きできる。
ホームの既定値は、本番の `homeFeed` の直近 3 日(2026-10-18〜21)のエントリ 1,075 件(Note 777・Announce 298)の平均で、
1 日約 358 件。リストは本番で数えていないので、ホームの件数にメンバーの割合(30 / 280)を掛けた 1 日約 38 件を使う。
東京リージョンの単価(読み取り $0.038 / 10 万回)で、無料枠(1 日 5 万回)を差し引く。
書き込み・Cloud Functions の実行時間・ストレージは含めない。

## 注意

- エミュレータはトランザクションのロックが悲観的なので、データは逐次に保存する。並列にするとロックの
  タイムアウトが多発する。
- 本番のデータの分布(リプライ・メンション・メディアの割合など)とは違うので、絶対値より前後の差を見る。

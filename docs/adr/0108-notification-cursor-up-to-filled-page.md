# ADR-0108: 通知の Link ヘッダのカーソルは、ページが埋まったところまでに読んだ範囲の端にする

- **Status:** Accepted
- **Date:** 2026-10-10
- **Supersedes:** [ADR-0089](0089-notifications-api.md) の「3. 読み足しと Link ヘッダ」のカーソルの定め方

## 背景

Issue #231 の確認で、`GET /api/v1/notifications?limit=5` の `rel="next"` が、6件目ではなく
40件先の通知を指していることが分かった。通知 API は1ラウンドで `max(limit * 2, 40)` 件を読み、
ADR-0089 に従って「読んだ全レコードの端」をカーソルにしていた。応答に入れたのは先頭の `limit` 件だけなので、
その間の通知はどのページにも出ない(Elk / Phanpy の通知タブをスクロールしても出てこない)。

## 決定

1. 読んだレコードを先頭から順に見て、応答の件数が `limit` に達したらそこで止める。
   **カーソルは、止めたところまでに見たレコード(除外したものを含む)の端の ID** とする。
2. 除外(破損データ・閲覧不可・`types` などのフィルタ)で `limit` に満たないあいだは、ADR-0089 のとおり
   読み足し、除外したレコードもカーソルの範囲に含める(空ページで止まらず、同じ範囲を読み直さない)。

お気に入り・ブックマーク(`social/noteCollections.ts`)と同じやり方である。

## 結果

- 通知を `limit` 件ずつ辿ると、すべての通知がちょうど1回ずつ出る。
- 1ラウンドで余分に読んだレコードは捨てる(次のページで読み直す)。読み出し回数は変わらない。

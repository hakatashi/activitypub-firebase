# ADR-0135: フォロー中の一覧を、射影のバージョンを見てインスタンス内にキャッシュする

- **Status:** Accepted
- **Date:** 2026-10-21

## 背景

Issue #342。`getFollowing` は呼ばれるたびに `userInfos/{actor}/following` の承認済みを全件読む(約 280 件)。
ホーム・リストのタイムラインは新着の無いポーリングでも 1 回あたり約 300 回の読み取りになり、その 9 割以上がこれである。
フォロー一覧は private な投稿の閲覧権限の判定にも使うため、古い一覧を返すとフォロー解除した相手の
private な投稿が見え続ける。

## 決定

1. **バージョン:** `userInfos/{actor}/projectionVersions/following` を置き、following の射影を書き換える
   Store のトランザクション(ADR-0082)の中で、射影のドキュメントを set / delete したときだけ書き直す。
   読み取り側はドキュメントの `updateTime` をバージョンとして使う。`rebuildFollowProjection` も最後に書き直す。
2. **キャッシュ:** `getFollowing` はまずバージョン(1 回の読み取り)を読み、前回の一覧を読んだときと同じなら
   インスタンスのメモリに置いた一覧を返す。違えば全件を読み直して、先に読んだバージョンで覚える。
   一覧より先にバージョンを読むので、間に書き込みが挟まっても次の呼び出しで必ず読み直す。
3. **バージョンが無いときはキャッシュしない。** 射影を直接書くテストや、デプロイ後まだフォローが一度も
   変わっていない本番でも、従来どおり毎回読むだけで、古い一覧は返さない。
4. **上限:** バージョンを経由しない書き込み(コンソールでの手直しなど)に備え、1 時間で読み直す。
5. `getExclusiveListMembers`・`loadViewer` の actor・`getPendingFollowTargetIris` はキャッシュしない。
   いずれも 1 回の呼び出しあたり数回の読み取りで、無効化の仕組みを足すほどの効果がない。

## 理由

- TTL だけでは、TTL の間フォロー解除した相手の private な投稿が見え続ける。バージョンなら書き込みと同時に反映され、
  費用は 1 回の読み取りで済む。
- 利用者は 1 人で一覧は数百件なので、インスタンスごと・コールドスタートで消えるメモリで足りる。
  Cloud Functions のインスタンスは複数あり得るが、どれも同じバージョンを見るので食い違わない。

## 結果

- フォロー 280 人での計測では、新着の無い `since_id` 付きのポーリングがホームで約 310 回から約 30 回、
  リストで約 290 回から約 10 回の読み取りになる。先頭ページを取り直す場合(`limit=20` で約 4,800 回)は
  約 280 回しか減らない。閲覧権限の判定で `getFollowing` を呼ぶほかのエンドポイントも 1 回あたり約 280 回減る。
- following の射影を書き換えるとき、書き込みが 1 件増える。
- 本番では、次にフォロー関係が変わるか `functions/bin/backfillFollowProjection.ts` を実行するまでキャッシュが効かない。

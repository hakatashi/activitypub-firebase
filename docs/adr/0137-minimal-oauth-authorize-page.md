# ADR-0137: OAuth 承認画面は、スマホで押せる最小限のスタイルだけを付ける

- **Status:** Accepted
- **Date:** 2026-10-21

## 背景

`GET /oauth/authorize` の承認画面は、クエリの生の JSON と、スタイルなしの「承認」ボタンだけだった。
利用者は 1 人なので機能上の問題はないが、スマホではボタンが小さく押しづらく、
何を許可しているのかも読み取りにくい。
自前の Web UI は作らない方針である ([ADR-0004](0004-no-custom-ui-use-elk.md)、[ADR-0107](0107-minimal-html-status-page-for-link-previews.md))。

## 決定

1. **この方針は維持する。** 承認画面は OAuth のフローに必須の 1 画面であり、手の込んだ UI にはしない。
2. 次の最小限だけを足す。
   - `viewport` の meta と、読みやすい幅・余白・フォントサイズ (インライン CSS のみ。CSS フレームワークや画像は使わない)
   - 生の JSON をやめ、クライアント ID・リダイレクト先・要求スコープ (一覧) を表示する
   - 画面幅いっぱいの、タップしやすい高さ (48px 以上) の「承認」ボタン
3. フォームの hidden フィールドと POST の挙動、Firebase UI によるログインは変えない。
4. 「拒否」ボタンは置かない。承認したくなければタブを閉じれば済む (利用者は 1 人)。
   OAuth の `access_denied` リダイレクトは必要になった時点で Issue を起こす。

## 結果

- 文言は日本語のまま。ダークモードやクライアント名の表示は行わない。
